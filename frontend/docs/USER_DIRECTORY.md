# User directory

The authenticated `/users` route renders the collaborator directory for accounts that have `users.view_directory` without `users.view`. It calls `GET /api/v1/users/directory` (`auth:sanctum` plus active-account middleware). `ListDirectoryRequest` authorizes `users.view_directory` or `users.view`; validates optional `search` (string, max 100), `department` (string, max 100), and `per_page` (integer 1–100, default 20); paginator reads the conventional `page` query parameter. The endpoint returns paginated `UserDirectoryResource` rows with the sanitized fields `id`, `name`, `email`, `avatar_url`, `timezone`, `job_title`, and `department`.

Search matches the backend's supported name, email, job-title, and department fields. The department filter is exact. Page size and pagination use the API's `meta.current_page`, `meta.last_page`, `meta.per_page`, and `meta.total`. Search and department input are debounced. Empty, loading, API failure, and retry states are explicit; a responsive table and card presentation share the same sanitized data.

The directory intentionally does not show account status, roles, permissions, or administrative details; those fields do not exist in `UserDirectoryResource`. Frontend permission checks control the route and navigation visibility; the backend request authorization is authoritative. HTTP 401 represents missing authentication, 403 represents authorization denial, and 422 represents invalid filters. Tests exercise direct-route denial (including seeded cached administrative rows), sanitized display even when excluded fields are present in a mock row, empty and loading states, API validation failure/retry, debounced search and clear, and next/previous/last-page query parameters. Search changes reset pagination and do not request the unsettled filter value. API service tests verify endpoint/query mapping without contacting Laravel.

The directory renders a desktop semantic table and mobile cards with `md:block` / `md:hidden` breakpoints; JSDOM tests verify both structures, not browser viewport pixels. No screenshot or real-device viewport verification is claimed.

The auth provider clears TanStack Query data on logout and when the in-memory token is cleared (including a current-token 401 or `ACCOUNT_NOT_ACTIVE` response). When a refreshed `/auth/me` response changes the effective permission set, the provider removes cached user-list/detail queries. Logging out before changing accounts clears cached administrative data. These updates occur when the frontend observes the new auth response; permission changes are not pushed in real time. Permission checks are a UI visibility layer; the Laravel endpoint continues to enforce access.
